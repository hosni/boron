# مدل ذهنی

این قواعد را در ذهن داشته باشید تا API قابل‌پیش‌بینی بماند.

## لحظهٔ زمانی میلادی است

یک نمونهٔ `Boron\Carbon` زیر پوست هنوز datetime میلادی است. getterها و
فرمت‌کننده‌های کربن (`->year`، `->format('Y-m-d')`، `addMonth()`، …) دقیقاً مثل
Carbon رفتار می‌کنند.

بقیهٔ تقویم‌ها یک **نمای** هستند برای:

- ساخت / پارس ورودی کاربر (`fromJalali`، `parseFromCalendar`)
- نمایش (`toJalali`، `calendarFormat`)
- حساب ماه/سال در همان تقویم (`addCalendarMonths`، …)

!!! important "ذخیره‌سازی"
    تاریخ‌ها را میلادی ذخیره کنید (ستون‌ها و castهای پیش‌فرض ISO در لاراول).
    فقط در مرز UI / ورودی تبدیل کنید. مگر دلیل خیلی خاصی داشته باشید،
    رشتهٔ جلالی را در دیتابیس نگه ندارید.

## تقویم فعال در برابر getterهای کربن

```php
$date = Carbon::parse('2024-03-20')->withCalendar('jalali');

$date->year;           // 2024  - میلادی (Carbon)
$date->calendarYear;   // 1403  - جلالی (تقویم فعال)
$date->format('Y-m-d');           // 2024-03-20
$date->toCalendarDateString();    // 1403-01-01
```

## تبدیل را دستی ننویسید

ریاضیات جلالی سفارشی، حلقه‌های `str_replace` برای ارقام، یا بریدن رشته ننویسید.
بورون از قبل تبدیل، پارس (از جمله ارقام فارسی/عربی-هندی)، قالب‌بندی و حساب
تقویمی را پوشش می‌دهد.

## Drop-in یعنی واقعاً drop-in

`Boron\Carbon instanceof Carbon\Carbon` برابر `true` است. هرجا Carbon پذیرفته
می‌شود، بفرستید. `toImmutable()` / `toMutable()` گونه‌های بورون را برمی‌گردانند و
تقویم فعال را نگه می‌دارند — هرگز Carbon ساده نشت نمی‌کند.
